Workspace, voice input (**General › Voice input**: OS dictation, the whisper.cpp CLI, model download and language, see Voice input below), CLI status (Claude Code, Codex, Grok Build, GitHub CLI, GitLab CLI, Git) and run preferences (`<workspace>/settings.json`). **General › Backlog › Default development workflow**: the workflow used wherever one is not picked by hand (the Product Owner's plans and its simulated plan, Split + roadmap, Create + roadmap, the Assign dialog with nothing remembered); unset, it is `software-development-local-hero.yaml` (local merge: no push, no PR, no CI minutes) when the workspace has it, else `software-development.yaml`; a saved workflow that was deleted or renamed falls back the same way, and Settings says so. **Execution › Keep awake**: the switch of the Workflows screen (see Workflows), off by default: no sleep while runs, a roadmap or a queue have work to do. **Execution › Concurrent runs**: off by default (one run at a time); on, several workflows run at the same time up to a **maximum** (default 2), with an optional **maximum per project**; simulations count toward the limits only if you say so. **Machine profile** (#367): Concurrent runs shows one line sizing the runs from this machine ("This machine: 20 threads, 32 GB → up to 5 runs at once, 1 test worker per run": runs = min(threads ÷ 4, GB ÷ 6), between 1 and 6; the test workers are the machine's divided by the runs), with its state: **Auto** (the maximum and the **test workers per run** follow the machine), **Manual** (a value you typed wins, stays as it is on another machine; **back to auto** drops it) or **Unknown** (the machine could not be read: 2 runs, 2 workers). **Use these values** turns concurrent runs on with the machine's values. Every run gets its test workers as `MULTIAGENT_TEST_WORKERS` / `MULTIAGENT_E2E_WORKERS`. When the memory guard held or stopped runs on 2 or more days of the last 7, it suggests one run fewer, with the days and runs, and changes nothing until you click **Apply** (Undo in its toast). **Execution › Memory guard** (#276): on by default; a process a real run started (a test, a build, a script, a suite or a screenshot capture) that uses more than the **limit** (25% of the RAM by default, 5–90; the hint gives it in GB for this machine) is stopped with its children within seconds, and suites and new real runs wait while less than the **floor** of the memory is free (10% by default, 0–50, 0 = no hold); the agent CLI itself, the app and your other programs are never stopped. **Execution › Oracle › Self-healing** (#278): off by default; on, the Oracle watches every run and roadmap day and night, with no end time, and repairs what its permissions allow (**What it may do alone (3 of 10)** opens the Night watch's checklist, one list for both); it never answers a gate, pushes, closes an issue or deletes data, and the row is disabled with the reason while the Oracle cannot start in the workspace. A value out of its range is marked and not saved; turning it off applies to the runs started afterwards. Each run has its own git worktree, and the monthly budgets count every run in progress. The **Run** menu item then lists the runs in progress (status, workflow, project/issue): click one to show it on the Run screen; a badge counts the human gates waiting across runs, and a gate never pops up over another screen: a toast names its run
