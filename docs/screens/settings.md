Workspace, voice input (**General › Voice input**: OS dictation, the whisper.cpp CLI, model download and language, see Voice input below), CLI status (Claude Code, Codex, Grok Build, GitHub CLI, GitLab CLI, Git; **Agents & CLIs › Orchestrator AI** (#97) chooses Claude Code or Codex as the AI that leads the runs, the Setup's **Use as orchestrator** radios, saved at once and used from the next run, never by one already running) and run preferences (`<workspace>/settings.json`). There is no global default workflow (#790): the workflow used wherever one is not picked by hand (the Product Owner's plans, Split + roadmap, Create + roadmap, the Assign dialog with nothing remembered, Fix the base) is the project's own default, from its page or its repository's `.craftorio/project.yaml`; an older `defaultWorkflow` setting is copied once to the projects without one and then dropped. **General › Language** (#327, #328, #329), next to the time zone: **Interface** (#329; English or Português (Brasil), the languages with a translation) sets the language of every screen (#330: Home, Inbox, Discovery, Backlog and Roadmap, Run, Sessions, Releases, Projects, Workflows, Agents, Skills, Analytics, Usage, Night watch, the Oracle, Product Owner and Supervisor drawers and the Agents window), the First-run setup, OS notifications and desktop dialogs, with dates, numbers and percentages in that language and costs in US$ with its separators ("US$ 6,48"); until you choose one it follows the computer's language when the app has it, else English, and a change redraws every open window at once, without a restart (your content, workflow texts, agents' messages and logs are not translated; to add a language, copy `packages/shared/i18n/en.json` to `<lang>.json`, translate its values and add it to `PAGE_LANGUAGES` in `packages/shared/i18n.js`; a key it lacks shows the English text); **AI agents** ("Same as the interface", the default, which follows the Interface language; or English, Português (Brasil), Español, Français, Deutsch, Italiano, 日本語, 中文, 한국어) sets the language of every chat reply (Oracle, Product Owner, Supervisor, Grill me), step summary, handoff note, decision log and generated document; **Issues** (English by default, same list) sets the language of issue titles and bodies, issue comments, PR/MR descriptions and review replies, and the commit messages agents write, with the headings the app writes itself (`## Tasks`, `Related:`, `Decision (owner):`) translated where the language has them. Each agent turn carries one Language line naming both; JSON keys and enum values, paths, branches, labels, `- [ ]` checkboxes, `#n` references and closing keywords (`Closes #n`) never change, and code comments follow the project. A change applies from each session's next turn. **Execution › Keep awake**: the switch of the Workflows screen (see Workflows), off by default: no sleep while runs, a roadmap or a queue have work to do. **Execution › Concurrent runs**: off by default (one run at a time); on, several workflows run at the same time up to a **maximum** (default 2), with an optional **maximum per project**; simulations count toward the limits only if you say so. **Machine profile** (#367): Concurrent runs shows one line sizing the runs from this machine ("This machine: 20 threads, 32 GB → up to 5 runs at once, 1 test worker per run": runs = min(threads ÷ 4, GB ÷ 6), between 1 and 6; the test workers are the machine's divided by the runs), with its state: **Auto** (the maximum and the **test workers per run** follow the machine), **Manual** (a value you typed wins, stays as it is on another machine; **back to auto** drops it) or **Unknown** (the machine could not be read: 2 runs, 2 workers). **Use these values** turns concurrent runs on with the machine's values. Every run gets its test workers as `CRAFTORIO_TEST_WORKERS` / `CRAFTORIO_E2E_WORKERS`. When the memory guard held or stopped runs on 2 or more days of the last 7, it suggests one run fewer, with the days and runs, and changes nothing until you click **Apply** (Undo in its toast). **Execution › Memory guard** (#276): on by default; a process a real run started (a test, a build, a script, a suite or a screenshot capture) that uses more than the **limit** (25% of the RAM by default, 5–90; the hint gives it in GB for this machine) is stopped with its children within seconds, and suites and new real runs wait while less than the **floor** of the memory is free (10% by default, 0–50, 0 = no hold); the agent CLI itself, the app and your other programs are never stopped. **Execution › Oracle › Self-healing** (#278): off by default; on, the Oracle watches every run and roadmap day and night, with no end time, and repairs what its permissions allow (**What it may do alone (3 of 10)** opens the Night watch's checklist, one list for both); it never answers a gate, pushes, closes an issue or deletes data, and the row is disabled with the reason while the Oracle cannot start in the workspace. A value out of its range is marked and not saved; turning it off applies to the runs started afterwards. Each run has its own git worktree, and the monthly budgets count every run in progress. The **Run** menu item then lists the runs in progress (status, workflow, project/issue): click one to show it on the Run screen; a badge counts the human gates waiting across runs, and a gate never pops up over another screen: a toast names its run
