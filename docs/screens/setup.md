The first-run Setup (#319), a large modal that opens once per workspace after the workspace folder and the sign-in (Settings › Agents & CLIs › **Run setup again** reopens it): a stepper of two steps, **Agents · First project**, with Back / Next / Skip (Enter = Next, Esc = Skip after a confirm). **Agents**: one row per CLI with its status (Ready / Not signed in / Not installed / Checking…), version, account and what it is for, and one action (**▶ Install** or **▶ Sign in**, run in the terminal dock; the row checks again when that terminal ends, and **Check again** checks them all). The step asks **Which AI do you want to use as the orchestrator?** (#97): the Claude Code and Codex CLI cards each have a **Use as orchestrator** radio (one choice, the arrow keys move it; Grok Build has none, it only reviews on a second model). A CLI that is not installed or not signed in cannot be chosen until it is ready; when only one of the two is ready it is chosen. The chosen card reads **Required** (with Git), the others **Optional**, and the note of what will not run names it. The choice is saved at once (`orchestratorProvider` in `settings.json`, Claude Code when none) and the default workflows feature, fix and release then run their orchestrator and agents on that AI's models (on Codex: Fable 5.2 → `gpt-6.2-astra`, Opus 5.5 → `gpt-6.2-sol`, Sonnet 5.5 → `gpt-6.1-terra`, Haiku 5.5 → `gpt-6-luna`); Start warns before a run when a mapped model is not in the Codex CLI's model list for the account. A custom workflow that names its provider is not changed. **First project**: the workspace's projects and **New project**, which opens the onboarding wizard (by itself when there is none); **Finish** opens Start, unless the onboarding left its project's page open. Setup never changes the simulation mode, which is off by default: the Product Owner and Start are real. Turn the simulation on, and see how many runs at once and test workers this machine allows, in Settings › Execution (**Developer mode**, **Concurrent runs**). Finish or Skip records `setupDone` in `settings.json`, so it never opens by itself again; workspaces created before Setup existed count as set up.
