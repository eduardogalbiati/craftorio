The first-run Setup (#319), a large modal that opens once per workspace after the workspace folder and the sign-in (Settings › Agents & CLIs › **Run setup again** reopens it): a stepper of two steps, **Agents · First project**, with Back / Next / Skip (Enter = Next, Esc = Skip after a confirm). **Agents**: one row per CLI with its status (Ready / Not signed in / Not installed / Checking…), version, account and what it is for, and one action (**▶ Install** or **▶ Sign in**, run in the terminal dock; the row checks again when that terminal ends, and **Check again** checks them all). **First project**: the workspace's projects and **New project**, which opens the onboarding wizard (by itself when there is none); **Finish** opens Start, unless the onboarding left its project's page open. Setup never changes the simulation mode, which is off by default: the Product Owner and Start are real. Turn the simulation on, and see how many runs at once and test workers this machine allows, in Settings › Execution (**Developer mode**, **Concurrent runs**). Finish or Skip records `setupDone` in `settings.json`, so it never opens by itself again; workspaces created before Setup existed count as set up.
