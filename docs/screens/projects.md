The projects (#354: in the menu under Code & Build, before Backlog; a tab of Settings from #254 until then): the project cards with **Start workflow**, **Open folder**, **Edit** and **Remove**, and **Open folder** (the projects' folder) and **New project** in the header; with no project, an empty state with **New project**. The header's selector chooses the one every screen shows, and opening a project makes it the header's. Projects in `<workspace>/projects/<id>.json`. Every project has a folder and optionally a git repository. With a repository and no folder, it is cloned into `<workspace>/repos/<owner>-<repo>`; without either, the folder is `<workspace>/projects/<id>/`. Clicking a card opens the project's page, with four tabs (the selected one is remembered per project; choosing another project in the header switches the page to it). **Overview**: the folder, the repository, the commits not pushed yet, and every workflow run in it (status, cost, task), and for each run its sessions, with **Live terminal** / **Open in CLI** to watch or resume any of them, then two columns: **Artifacts** (what the run produced first, **Show all** for its notes and logs, chips by category and kind, as in the run's Details) and **Repository** (the run's branch and its state, its commits newest first, **Review changes** opening the changes viewer, a click on a commit opening it on that commit). Runs are linked by the project id they were started with (older ones by the project's current or previous folders). **Conflict map**: one table of the files most runs edit, merging the saved conflict map (see The conflict map) and the repository performance of a date range: each file with the runs that edited it, its share of the runs (marked past the shared limit), a **hot** badge past the Product Owner's threshold (more than half of the last 20 runs) and the merge conflicts that named it; a click on a row shows the runs behind the count, the single lines of that file most changed, the trend (the newer half of the map's runs against the older half) and the file's recommendation with **Create issue**. Its controls: 7, 30 or 90 days or a From-To range, the before/after marker, **Refresh** and **Ask for a plan** (the supervisor's suggestion for the files over the limit, a real model call it asks for first). It says when the folder is not a git repository or no run with commits is in the range. **Architecture** and **Refactor**: what they will hold (the code analysis, the prioritized refactors), built by their own issues
