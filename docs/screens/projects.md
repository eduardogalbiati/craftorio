The projects (#354: in the menu under Code & Build, before Backlog; a tab of Settings from #254 until then): the project cards with **Start workflow**, **Open folder**, **Edit** and **Remove**, and **Open folder** (the projects' folder) and **New project** in the header; with no project, an empty state with **New project**. The header's selector chooses the one every screen shows, and opening a project makes it the header's. Projects in `<workspace>/projects/<id>.json`. Every project has a folder and optionally a git repository. With a repository and no folder, it is cloned into `<workspace>/repos/<owner>-<repo>`; without either, the folder is `<workspace>/projects/<id>/`. Clicking a card opens the project's page, with four tabs (the selected one is remembered per project; choosing another project in the header switches the page to it). **Overview**: the folder, the repository, the commits not pushed yet, and every workflow run in it (status, cost, task), and for each run its sessions, with **Live terminal** / **Open in CLI** to watch or resume any of them, then two columns: **Artifacts** (what the run produced first, **Show all** for its notes and logs, chips by category and kind, as in the run's Details) and **Repository** (the run's branch and its state, its commits newest first, **Review changes** opening the changes viewer, a click on a commit opening it on that commit). Runs are linked by the project id they were started with (older ones by the project's current or previous folders). **Conflict map**: one table of the files most runs edit, merging the saved conflict map (see The conflict map) and the repository performance of a date range: each file with the runs that edited it, its share of the runs (marked past the shared limit), a **hot** badge past the Product Owner's threshold (more than half of the last 20 runs) and the merge conflicts that named it; a click on a row shows the runs behind the count, the single lines of that file most changed, the trend (the newer half of the map's runs against the older half) and the file's recommendation with **Create issue**. Its controls: 7, 30 or 90 days or a From-To range, the before/after marker, **Refresh** and **Ask for a plan** (the supervisor's suggestion for the files over the limit, a real model call it asks for first). It says when the folder is not a git repository or no run with commits is in the range. **Architecture**: a **Facts | City** switch leads it (the choice is remembered per window). **Facts**: the latest Oracle report (summary, a verdict per area, findings with **Send to Refactor**), **Analyze with the Oracle** with its estimate, and the git facts (hotspots, the Danger Zone scatter, exclusions, the quality gate). **City**: the project as a 3D city drawn like the run's 3D view (same themes and toggle): a building per file (its footprint grows with the lines, its height with the complexity, floors with the functions, an antenna for the worst function), districts inside zones in the city plan's order with avenues and streets between them, landmarks with a beacon, ports past the edge with arcs to the files that talk to them. The header names the project, its files, zones and districts, the Danger Zone count, the plan's coverage and the commit; **Colour by** Quadrant, Zone or Churn with its legend, a **Tests** toggle, and a search that flies to a file or a district. Hovering shows a card and the arcs to what a file requires and what requires it; a click pins the card, whose **Open in Facts** shows the file's hotspot row. Without a city plan the districts are the folders, with **Map this project** and its estimate; a stale plan, the plan's problems and over 5,000 files (small files grouped per district) are noted under the header; without WebGL the view says so and points to the Facts. The City shows the agents of the project's runs in progress at work, live: a card lists each agent with its robot, name and step, standing on the roof of the file it last changed or at the door of the file it reads (a click opens its run); each run's last 10 changed files light up in its colour, a building with uncommitted changes gets a crane, a new file is a building under construction in its district, and a building two runs in progress change is marked as a **collision risk** with a link to the Conflict map. With no run in progress it says "No agent is working on this project"; runs of other projects are not shown. **Replay on the map** on a finished run's screen opens its project's City and plays the files its agents touched, with a timeline, **Play** / **Pause** and a speed. **Refactor**: the proposals sent from the Architecture findings
