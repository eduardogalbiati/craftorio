# Code map

Read this when you need to find where something lives. One row per file or group of files.

| File | What it does |
|---|---|
| `src/engine/workflow.js` | Engine. `loadWorkflow`, `WorkflowRun` (graph walk, transitions, `/goal` + `/loop`, delegation, fan-out `agents: [...]`, `save_as`, `on_error`, schema validation + retries, skills injection with `uses:`, budgets check per turn, decision log `decisions.tsv`, AI supervisor `superviseFailure`, resume from step, per-run worktree lifecycle `setupWorktree`/`finishWorktree`, run outcome from the ending transition's `status`, `mockSequences` option to steer the mock per field in tests, `github_repo` filter validating `pr_url` for the merge action). Session modes (`persistent` / `ephemeral` / `handoff`), handoff notes (`takeHandoff`, `saveHandoff`, `requestHandoffNote`), `max_context` rotation, per-turn context metrics (`turnLog`, `contextSummary` → `summary.context`). `sendToAgent` builds one turn; `invokeTurn` runs it against the provider. Exports `render` (nunjucks, autoescape off, filters `to_yaml`, `to_json`, `shuffle(seed)`), `takeHandoff`, `parseTokens`. |
| `src/engine/capabilities.js` | Agent capabilities (`tools`, `web`, `mcp`, `subagents`) and isolation → each CLI's flags (`providerArgs`), `validate` (used by `loadWorkflow`), `merge` (step over agent), `dedupeFlags`, `describe` (Workflows screen, run log). See [capabilities.md](capabilities.md). |
| `src/engine/providers.js` | CLI adapters and stream parsers: claude-code, codex-cli, grok-cli (NDJSON deltas, `--prompt-file` via `prompt_file_arg`), mock. Parsers emit `context` items (each request's context window: Claude's `assistant` usage outside sub-agents, Grok's per-call `usage`; Codex reports none). `resolveCommand` finds CLIs on Windows. The mock grows its context 30k per turn of a conversation and writes handoff notes when asked. |
| `src/engine/simulation.js` | Simulation-only guard (`MULTIAGENT_SIMULATION_ONLY=1`, set by every automated check): `simulationOnly()`, `refuseReal(what)`. Called by `providers.runTurn` (non-mock providers) and the service (real runs, Backlog assignments, CLI terminals); `app:info.simulationOnly` drives the UI badge. See [testing.md](testing.md). |
| `src/engine/probes.js` | Checks of `wait:` steps, run by the engine between agent turns (no tokens): `pr_checks`, `pr_changes` (fingerprint), `workflow_run` over `gh pr view` / `gh run view` / `glab mr view` / `glab api` pipelines. `parseTarget` (PR/MR and run URLs, anything else refused before a CLI starts) and the pure classifiers `ghPrState`, `ghRunState`, `glMrState`, `glPipelineState` (tested on JSON samples). |
| `src/engine/worktree.js` | Per-run git worktrees: `prepareWorktree` (prune, fetch `origin/<base>` with fallbacks, `worktree add --detach`; reuse or recreate from the run's branch on resume), `removeWorktree` (deletes the local branch only if merged, squash merges included via `git cherry`), `cleanupWorktrees` (at app start: succeeded runs and worktrees unused for 14 days). `canonicalPath`/`samePath` (realpath: 8.3 names, symlinks, junctions): use them for any path compared with or made relative to git output. |
| `src/engine/processes.js` | Stops what agents left running in a run's worktree (`stopProcessesIn`): executable inside it (Windows via `Get-CimInstance Win32_Process`, Linux `/proc`, macOS `ps`), or cwd inside it on Linux/macOS without a tty; whole process tree; spares this process, its ancestors and descendants (embedded terminals). `selectProcesses` is the pure part (tested on fake lists). The engine calls it after each agent step/delegation and at run end (`stopProcesses` option; none for mock runs), logging `worktree.processes_stopped` + a `worktree_processes` warn. |
| `src/engine/recorder.js` | `events.jsonl`, `sessions/<id>.jsonl`, `summary.json` per run. |
| `src/service/index.js` | Engine service, no Electron: `createService({ host })` → `api` (channel → fn: workflows, projects, skills, runs, usage, artifacts, supervisor, embedded terminals), `notifications` (`term:input`/`term:resize`), `events` (`run:event`, `term:data`, `term:exit`), plus helpers for the desktop layer. `host` = `trashItem`, `appVersion`, `isPackaged`. Owns the runs in progress (`active`, by run id; `startWorkflowRun`, also used to resume): the limit of concurrent runs (`concurrency`/`slotProblem`, setting `concurrentRuns`, starts under way are `reserved`), `runs:active`, and channels that take a `runId` (`run:stop`, `approval:resolve`: gate ids repeat across runs). Concurrent runs share budgets through `peerSessions` (the engine's per-turn check) and `usage.withPeerUsage` (preflight). Meant to be exposed over HTTP/WS later; keep Electron out of it. |
| `src/server/index.js` / `scripts/serve.js` | HTTP + WebSocket transport for the service (`npm run serve`): `POST /api/<channel>` `{arg}` → `{result}`/`{error}`, `/ws` pushes `run:event`/`term:*`/`auth:changed` and takes `term:input`/`term:resize`, serves the UI (only `src/renderer/` + the whitelisted `node_modules` libs). Token via Bearer header or the HttpOnly SameSite=Strict cookie set by `/?token=`; cross-origin requests refused. `src/renderer/api-http.js` builds `window.api` over it when there is no preload (a test keeps its method list equal to `preload.js`). Server session in `~/.multiagent-orchestrator/server-account.json` (0600, not OS-encrypted); `trashItem` moves to `<workspace>/.trash`. |
| `src/main.js` | Electron main: window, workspace dialog, IPC transport (registers every `service.api` channel), desktop-only actions (native dialogs, clipboard, open path/artifact, external console, workspace change). |
| `src/auth.js` / `src/auth-config.js` | Account sign-in (Supabase Auth, OAuth: system browser + PKCE + one-shot loopback server on `127.0.0.1:47823/auth/callback`) and the 7-day trial. No Electron: main passes a `fileStorage` encrypted with `safeStorage` (`%APPDATA%/…/account.bin`). `assertCanRun({ mock })` gates `run:start`/`supervisor:resume` via `host.assertCanRun` (simulations always allowed). Entitlement comes from the SQL function `entitlement()` (server clock), cached 3 days for offline use. `auth-config.js` holds the public URL + publishable key and the enabled providers (only `google` for now). Dev only: `MULTIAGENT_SUPABASE_URL`/`_KEY` override, `MULTIAGENT_AUTH=off` disables; the packaged app ignores them and always requires sign-in. |
| `supabase/migrations/` | `accounts` table (`trial_ends_at` = now + 7 days via trigger on `auth.users`, `plan` trial/pro, RLS read-own only) and `entitlement()`. Applied by pasting into the Supabase SQL editor. |
| `src/preload.js` | `window.api` exposed to the renderer (sandboxed; no Node there). |
| `src/renderer/duo.js` / `robots.js` | Write & Review screen: setup (prompt, goal, writer/reviewer CLI + model + effort) and the run as a chat rebuilt from run events, live or replayed (`runs:events`, "Open chat" in the runs list). `robots.js` draws the isometric robot avatars (variant per provider, animated states, model name plate, mirroring). |
| `src/renderer/arena.js` / `arena-shuffle.js` | AI Arena screen: setup (request, optional project, document skill, peer review, lenses, 2–5 contenders with CLI + model + effort) and the ai-arena run as a chat (proposals, blind critiques with the real authors, synthesis, verifier, the supervisor's gate inline, peer-score board), live or replayed ("Open chat"). Reuses duo.css + `window.ChatModels` from duo.js. `arena-shuffle.js` mirrors the engine's `shuffle` filter (inline SHA-256) to map "Proposal N" to its author; a test keeps them equal. |
| `src/renderer/run-chat-model.js` / `run-chat.js` | Run chat for any workflow run (view `runchat`): `RunChatModel` (pure, tested in `test/run-chat.test.js`) turns run events into items (agent turns with tool calls/thinking, handoff note and context start → peak, fan-out groups, transitions/loops/`/goal` lines, `max_context` rotations, gates + replies, supervisor decisions); `run-chat.js` draws only the items an event touched, answers gates inline (`runChatShowsRun` keeps the approval dialog closed) and routes writer-reviewer / ai-arena runs to their own screens (`window.openRunChat`). Opened from "Open chat" in the runs lists, Backlog run links and the Run screen's Chat / Details toggle. |
| `src/renderer/run-progress-model.js` | Run progress by the workflow's `groups:` (pure, tested in `test/run-progress.test.js`, also required by the engine and `src/runs.js`): `StepTrail` turns run events into step visits with their agents (engine → `summary.progress`; `runs.js` rebuilds it from `events.jsonl`, cached by mtime+size; the UI feeds it `run:event`), `progressGroups` folds them into the runs list's chips (visited groups only, ×N on a return, the last one with the run's state). Drawn by `runProgressStrip` in `app.js`; `renderSteps` groups the Run screen's sidebar. |
| `src/renderer/` | Plain HTML/CSS/JS UI, no bundler. See [renderer.md](renderer.md). |
| `src/workflow-builder.js` / `src/renderer/builder.js` | Visual builder (Workflows › Builder, issue #26). `toYaml(spec, base)` writes a regular workflow (inputs `task` + `project_path`, one agent per desk, human gates with `approved` → next / reject → `end` cancelled or back to a desk, AI gates (`reviewer: 'ai'`: an agent step with `AI_SCHEMA` { approved, notes }, reject → `end` failed or back to a desk with a `loop` of `maxRounds`, the desk's prompt gets the notes), `x-builder` with briefs and imported looks; `base` keeps the edited file's providers/defaults/orchestrator/observability); `fromWorkflow(doc)` reads it back and lists `problems` (what the builder can't draw: loops, fan-out, schemas, other inputs, hand-edited prompts). `describeWorkflow` / `patchWorkflow` show any workflow as a "fixed" spec (steps with badges, `agents` by name, `templated` fields) and write back only agents and prompts; `cloneText`. Service: `builder:load` (mode `full` / `fixed` / `readonly` = bundled), `builder:save` (refused for bundled files; checked with `loadWorkflow` before replacing the file), `builder:clone`, `builder`/`builderProblems` on `workflows:list`. `builder.js` draws the canvas with `Robots.desk` / `Robots.gate` (robots.js). |
| `src/workflows.js` | Skill CRUD, `resolveSkill` (workspace first, then bundled `skills/`), `skillPrompt`, `seedSkills` (copies bundled skills once, updates untouched copies by content hash, `.seeded.json`). |
| `src/agents.js` | Agents menu: user-defined agents in `agents/<id>.json` (name, description, prompt, skills, `appearance` = { body, shell, visor, glow, eyes, emblem }). The built-in supervisor is always first, can't be removed and only saves its look (`agents/supervisor.json`). EYES/EMBLEMS must match `robots.js` (a test checks). Renderer: `src/renderer/agents.js`; `Robots.define('supervisor', look)` recolors it in Write & Review. Not used by workflows yet. |
| `src/workspace.js` | Workspace path (registry / env) and `layout()` (`runs`, `repos`, `worktrees`, ...); exports `gitAuthArgs` (gh credential helper for clone/fetch). |
| `src/projects.js` | Projects; a project with a repo and no folder is cloned into `repos/`; `previousFolders` kept when the folder changes. |
| `src/backlog.js` / `src/renderer/backlog.js` | Backlog screen: a project's issues via `gh issue list` / `glab issue list` (Bitbucket: no sync yet), cached in `<workspace>/backlog/<id>.json`; `linkRuns` ties runs to issues (`run.issue` recorded by the engine, else task/inputs mentioning the URL or `#n`, mock runs excluded) and picks the kanban column (todo / in_progress / waiting / done). Each sync also reads the open PRs/MRs (`fetchOpenPullRequests`, `referencedIssues`: closing keywords, issue links, `#n` in the title, GitHub's `closingIssuesReferences`) into `issue.pullRequests` (a failure only sets `pullRequestsError`). Assigning a workflow queues issues in `<id>.queue.json` (`enqueue`, recording the PRs the user accepted as `knownPullRequests`; `runInputs`); right before a real (not simulated) start `dispatchQueue` calls `newPullRequests` and `skipQueued` (the queue's `skipped` list with the reason, dismissed with `unqueue`); the service's `dispatchQueue` starts queued issues while there are free run slots, oldest first across projects, a project at its own limit waiting (`nextQueued(dir, canStart)`; after each `workflow.finished` and a change of `concurrentRuns` too); queues are paused on `setWorkspace`, on a failed start and when a queued run fails. Default platform: setting `backlogPlatform`. IPC `backlog:get`/`sync`/`assign`/`unqueue`/`pause`. |
| `src/runs.js` | Runs on disk (`readRun`/`listRuns`, interrupted runs rebuilt from events), `runsForProject` (project id, else folders), `projectOf` (a run's project), `runArtifacts` (includes `handoffs/*.md`). The same run list component is shown in Projects > Project and Workflows > Runs (IPC `projects:runs` and `runs:list`, shared `runListItem`). |
| `src/usage.js` / `src/local-usage.js` | Token/cost usage per provider (scope orchestrator vs this machine from the CLIs' own logs: ~/.claude/projects, ~/.codex/sessions, ~/.grok/sessions), Codex plan limits/credits, budgets, `preflight` (missing CLI, budget, empty folder inputs). |
| `src/supervisor.js` | AI supervisor: decision/analysis schemas, prompts (with the agents' latest handoff notes), `runReport`, `analyzeRun` (saves `supervisor/analysis-*.md`; read-only + isolated via `capabilities.providerArgs`), `resumeSpec` (also returns the run's `worktree: { dir, branch }` and the latest handoff note per agent). Skill: `skills/run-supervisor`. |
| `src/notifications.js` | Desktop notifications, no Electron: `runNotice` (started / waiting at a gate / succeeded / failed / cancelled; `interruptedNotice` for the run in `<workspace>/active-run.json` at the next start), `WaitDetector` (a Sessions terminal whose CLI, after the user typed, goes quiet for 8 s with a prompt-like line at the end of its output (`promptLine`: question, y/n, numbered choice, empty input box; none while "esc to interrupt" shows), or writes OSC 9 / OSC 777 / a bell, is waiting), `shouldNotify` (settings `notifyRuns`/`notifySessions`; nothing about the run/terminal the focused window shows, reported by the UI on `notify:context`). The service emits `notify`; main shows it with Electron's `Notification`, a click sends `notify:open` to the renderer. |
| `src/terminals.js` / `src/session-tail.js` | Embedded terminals: node-pty pseudoterminals (CLI resume, supervisor chat) and virtual terminals (live log follower, no process). |
| `src/cli-sessions.js` / `src/renderer/sessions.js` | Sessions screen (first menu item): lists the CLIs' own conversations on this machine (head/tail of each file, cached by mtime+size; `CLI_PROVIDERS` = interactive new/resume args, `cliArgs` rejects unsafe values) and runs the CLIs in embedded terminals (`term:open` kinds `cli-resume` — folder looked up server side, never from the caller — and `cli-new`). The service tags sessions with their project and `workflowAgent` (headless, or in `runs/`/`worktrees/`). Terminals there reuse app.js's `createXterm`/`wireTerminal`; `SessionsView.findTab` routes `term:data`. In automated checks put a fake **`.exe`** first on PATH (`resolveCommand` prefers any `.exe` over a `.cmd`) or a real CLI starts. Folders inside the workspace are pre-trusted in each CLI's own config (`src/cli-trust.js`; Claude's trust does not cross a git root, so the folder and its repo root are written). Titles the user gives live in `<workspace>/session-titles.json` (the CLIs' files are never edited). Codex runs with `--no-daemon` (the shared app-server refuses the WinGet install and would outlive the terminal). `Terminals.kill` kills the whole process tree (taskkill /T; `pgrep -P` elsewhere). |
| `workflows/*.yaml` | `software-development` (language + git_platform inputs pick skills), `ai-arena` (2–5 user-picked models compete → blind critique → base+graft synthesis → verify → human review), `multi-model-review`, `run-retrospective`, `writer-reviewer` (user-picked writer/reviewer loop until a score threshold, internal Opus 5.5 sign-off). |
| `skills/` | 41 bundled skills (see the README table). |
| `docs/agents/` | These topic docs, indexed by `CLAUDE.md` (`test/claude-md.test.js` keeps the index small and its links valid). |
