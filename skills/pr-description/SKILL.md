# PR/MR description

Inspired by the pr skill in mattpocock/skills (MIT). Platform-neutral: the ci-pipeline skill
tells you which command sets the title and body.

## Title

Imperative mood, under 70 characters, says what changes for the user or the system
("Retry failed webhook deliveries with backoff"), not the files touched.

## Body

Use exactly these sections:

```
## Summary
<one or two sentences: what and why, linking the task/issue if there is one>

<the smallest visual that makes the change clear, next to the sentence it supports:
 - logic change      → short pseudocode or a focused before/after snippet
 - runtime flow      → call tree or a Mermaid sequence diagram
 - structure change  → file tree of what was added/moved
 - UI change         → note that the preview has screenshots>

## Evidence
- tests: <command> → <pass/fail counts>; new or changed tests: <names>
- build/audit: <result>
- preview: <URL, once the deploy step publishes it>

## Merge danger
- door: one-way | two-way   (can this be reverted by a simple revert?)
- blast radius: <one word: file | module | service | data | everyone>
- rollback: <how, and what it costs>  (only for one-way doors)
```

## Rules

- Evidence is what you ran, not what should work.
- One-way doors: data migrations, deleted data, changed public APIs or event formats,
  external side effects. Say it plainly.
- No secrets, tokens or internal URLs that are not already in the repository.
- End the body with `(description generated by an AI agent)`.

## Done when

The PR/MR has a title under 70 characters and a body with all three sections filled with real values.
