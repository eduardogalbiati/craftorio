      How Write & Review works
      
        
      
      
      
      
        
      Three AI agents write a document for you. A writer drafts it, a reviewer scores it against your goal and sends notes back until it passes, and the supervisor checks the result and asks you what to do. You follow it as a chat, and you decide at the end.
      
        
      

        
      1. Set up a run
      
        
        
          
      • Prompt: what to write (a PRD, a migration plan, a blog post…).
        • 
          
      • Goal: when the document is good enough. The reviewer scores every draft against it, so make it concrete ("every requirement is testable", "metrics have targets").
        • 
          
      • Project (optional): the writer and the reviewer work in the project's folder and read its files to ground the document. They are read-only there: they can't create, edit or delete anything, and the drafts are saved in the run folder, not in the project.
        • 
          
      • Approve at: the minimum score (0-10) for a draft to pass. Max rounds: how many reviews before you are asked what to do.
        • 
          
      • Writer and reviewer: pick the CLI (Claude Code, Codex, Grok), the model and the effort of each one. Different models in the two roles give the review a second perspective. The supervisor is the platform's own agent: it is fixed and not configurable.
        • 
        
      

        
      2. The flow
      
        
      
          Write→Review→score ≥ approve at?→Supervisor check→You decide→Done
        
      
        
        
          
      • Below the score, the reviewer's notes go back to the writer, who sends a new version (v2, v3…). The reviewer also checks whether its previous notes were addressed.
        • 
          
      • The engine decides whether a draft passes, from the score and your threshold. The agents don't.
        • 
          
      • If the rounds run out, the supervisor asks you: accept the last draft, one more round, or stop.
        • 
          
      • When a draft passes, the supervisor checks it against each part of your goal ("✓ Ready" or "↺ Not ready yet") and recommends what to do.
        • 
        
      

        
      3. Talking to the supervisor
      
        
        
          
      • The supervisor always asks you before the run ends: accept the document, send it back to the writer, or stop.
        • 
          
      • You can also type instructions, e.g. "Keep the pricing and the launch date as open questions: they are decided later". Your instructions go into every later prompt of the writer, the reviewer and the supervisor. They take precedence over the goal, and the reviewer won't count them against the draft.
        • 
          
      • Nothing crosses these questions automatically: the run waits for you.
        • 
        
      

        
      4. Reading the chat
      
        
        
          
      • Robots: one per model (Claude, ChatGPT, Grok…), with the model on its name plate. The robot below the last message shows what the agent is doing right now: thinking, reading, writing, waiting for you, error, done. The same states are shown for all three agents in the header.
        • 
          
      • Writer messages carry the draft (document.md · vN): click it, or use v1, v2… in the Document panel, to read any version.
        • 
          
      • Reviewer messages show the score and its bar (the tick is your threshold), a summary and the notes. major notes block approval and minor notes don't. The header chart shows the score per round.
        • 
          
      • The Supervisor panel lists what it checked and each intervention. Every message shows its tokens, cost and time. Stop ends the run and Run folder opens its files.
        • 
        
      

        
      5. When something goes wrong
      
        
        
          
      • If an agent's answer doesn't have the expected format, it's rejected (red robot) and the agent is asked again, up to twice.
        • 
          
      • If it still fails, the supervisor steps in: it explains what happened and retries with an instruction, or asks you. It routes problems to the agents and never edits the document itself.
        • 
          
      • Real runs check before starting that the CLIs are installed, the budgets allow it and the project folder exists.
        • 
        
      

        
      6. Where the results are
      
        
        
          
      • In the run folder: document.md (the last version) and drafts/v1.md, v2.md…, plus the full log of the run. They also show up in Artifacts.
        • 
          
      • Every run is in Workflows › Runs, and under the project when you picked one. Open chat replays the conversation, or follows it if it's still running.
        • 
          
      • Under the hood it's the writer-reviewer workflow (Workflows › Definitions), which you can also start from the Start panel.
        • 
        
      

        
      7. Simulation (developer mode)
      
        
        
          
      • Turn on Settings › Execution › Developer mode to see the Simulation checkbox (checked by default). Simulated agents call no CLI and cost nothing.
        • 
          
      • The Scenario picker sets what the simulated agents do: approved on the 3rd review (5.5 → 7 → 8.6), approved on the 1st, never reaches the score (the rounds run out), the supervisor finds gaps, the reviewer answers in the wrong format (the supervisor steps in).
        • 
          
      • Real runs use your CLIs' plans. Every round is a writer turn and a reviewer turn, plus one supervisor check at the end.
